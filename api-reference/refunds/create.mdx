description: "Issue a full or partial refund for a captured payment via the XPayLabs API. Provide payment_id and an optional amount. Returns a Refund object."
---

To issue a refund, provide the ID of the captured payment you want to refund along with an optional `amount`. If you omit `amount`, XPayLabs refunds the full captured amount. Partial refunds are supported — you can issue multiple partial refunds against the same payment as long as the cumulative refunded amount does not exceed the original charge. Refunds are processed asynchronously; the returned object will initially have a `status` of `pending` before transitioning to `succeeded` or `failed`.

## Request

**`POST https://api.xpaylabs.com/v1/refunds`**

### Request Body

<ParamField body="payment_id" type="string" required>
  The ID of the payment you want to refund. The payment must be in a `captured` state. Example: `pay_abc123xyz`.
</ParamField>

<ParamField body="amount" type="integer">
  The amount to refund, expressed in the smallest currency unit (e.g., cents for USD). If omitted, the full captured amount is refunded. Must be greater than zero and cannot exceed the remaining refundable amount on the payment.
</ParamField>

<ParamField body="reason" type="string">
  An optional reason for the refund. Accepted values are `duplicate`, `fraudulent`, and `requested_by_customer`. This value is stored on the Refund object and may be passed to the card network for dispute resolution.
</ParamField>

<ParamField body="metadata" type="object">
  A set of key-value pairs you can attach to the refund for your own record-keeping. Keys and values must be strings. Up to 50 keys are allowed, with key names up to 40 characters and values up to 500 characters.
</ParamField>

## Examples

### Full Refund (cURL)

```bash
curl -X POST https://api.xpaylabs.com/v1/refunds \
  -H "Authorization: Bearer sk_live_yourkey" \
  -H "Content-Type: application/json" \
  -d '{
    "payment_id": "pay_abc123xyz",
    "reason": "requested_by_customer"
  }'
```

### Partial Refund (cURL)

```bash
curl -X POST https://api.xpaylabs.com/v1/refunds \
  -H "Authorization: Bearer sk_live_yourkey" \
  -H "Content-Type: application/json" \
  -d '{
    "payment_id": "pay_abc123xyz",
    "amount": 2500,
    "reason": "duplicate",
    "metadata": {
      "order_id": "ord_98765",
      "initiated_by": "support_agent"
    }
  }'
```

### Node.js

```javascript
import XPayLabs from "xpaylabs";

const client = new XPayLabs({ apiKey: "sk_live_yourkey" });

// Full refund
const fullRefund = await client.refunds.create({
  payment_id: "pay_abc123xyz",
  reason: "requested_by_customer",
});

console.log(fullRefund.id); // ref_xyz789abc

// Partial refund
const partialRefund = await client.refunds.create({
  payment_id: "pay_abc123xyz",
  amount: 2500,
  reason: "duplicate",
  metadata: {
    order_id: "ord_98765",
    initiated_by: "support_agent",
  },
});

console.log(partialRefund.status); // "pending"
```

## Response

A successful request returns a **Refund object** with HTTP status `200`.

<ResponseField name="id" type="string">
  Unique identifier for the refund. Example: `ref_xyz789abc`.
</ResponseField>

<ResponseField name="object" type="string">
  Always `"refund"`.
</ResponseField>

<ResponseField name="payment_id" type="string">
  The ID of the original payment that was refunded.
</ResponseField>

<ResponseField name="amount" type="integer">
  The refunded amount in the smallest currency unit (e.g., `2500` = $25.00 USD).
</ResponseField>

<ResponseField name="currency" type="string">
  Three-letter ISO 4217 currency code in lowercase (e.g., `"usd"`).
</ResponseField>

<ResponseField name="status" type="string">
  Current processing status of the refund. One of `pending`, `succeeded`, or `failed`.
</ResponseField>

<ResponseField name="reason" type="string | null">
  The reason provided when the refund was created. One of `duplicate`, `fraudulent`, `requested_by_customer`, or `null` if no reason was supplied.
</ResponseField>

<ResponseField name="failure_code" type="string | null">
  If `status` is `failed`, this field contains a machine-readable code describing why the refund failed. `null` otherwise.
</ResponseField>

<ResponseField name="metadata" type="object">
  The key-value metadata attached to this refund at creation.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp indicating when the refund was created. Example: `"2024-06-15T10:30:00Z"`.
</ResponseField>

### Example Response

```json
{
  "id": "ref_xyz789abc",
  "object": "refund",
  "payment_id": "pay_abc123xyz",
  "amount": 2500,
  "currency": "usd",
  "status": "pending",
  "reason": "duplicate",
  "failure_code": null,
  "metadata": {
    "order_id": "ord_98765",
    "initiated_by": "support_agent"
  },
  "created_at": "2024-06-15T10:30:00Z"
}
```

## Error Responses

| HTTP Status | Error Code | Description |
|---|---|---|
| `400` | `amount_exceeds_original` | The requested refund amount exceeds the remaining refundable amount on the payment. |
| `404` | `payment_not_found` | No payment with the provided `payment_id` was found in your account. |
| `422` | `already_fully_refunded` | The payment has already been fully refunded and no additional refunds can be issued against it. |

<Warning>
  Refunds cannot be reversed once submitted. Before calling this endpoint, confirm the payment ID, amount, and reason are correct. If you need to re-charge a customer after an accidental refund, you must create a new payment.
</Warning>
