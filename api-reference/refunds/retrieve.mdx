Use this endpoint to retrieve a refund's full details and current processing status by its unique refund ID. This is useful for polling the status of a refund after creation — for example, confirming that a `pending` refund has transitioned to `succeeded` — or for auditing refund records associated with a payment. For real-time status updates, consider listening to the `refund.succeeded` and `refund.failed` [webhook events](/api-reference/webhooks/events) instead of polling.

## Request

**`GET https://api.xpaylabs.com/v1/refunds/{id}`**

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the refund to retrieve. Refund IDs are prefixed with `ref_`. Example: `ref_xyz789abc`.
</ParamField>

---

## Example

### cURL

```bash
curl -X GET https://api.xpaylabs.com/v1/refunds/ref_xyz789abc \
  -H "Authorization: Bearer sk_live_yourkey"
```

---

## Response

A successful request returns the **Refund object** with HTTP status `200`.

<ResponseField name="id" type="string">
  Unique identifier for the refund. Example: `ref_xyz789abc`.
</ResponseField>

<ResponseField name="object" type="string">
  Always `"refund"`.
</ResponseField>

<ResponseField name="payment_id" type="string">
  The ID of the original payment that was refunded. Example: `pay_abc123xyz`.
</ResponseField>

<ResponseField name="amount" type="integer">
  The refunded amount in the smallest currency unit (e.g., `5000` = $50.00 USD).
</ResponseField>

<ResponseField name="currency" type="string">
  Three-letter ISO 4217 currency code in lowercase. Example: `"usd"`.
</ResponseField>

<ResponseField name="status" type="string">
  Current processing status of the refund. One of:
  - `pending` — the refund has been submitted and is awaiting processing.
  - `succeeded` — the refund was processed successfully and funds are being returned.
  - `failed` — the refund could not be processed; see `failure_code` for details.
</ResponseField>

<ResponseField name="reason" type="string | null">
  The reason the refund was issued. One of `duplicate`, `fraudulent`, `requested_by_customer`, or `null` if no reason was provided at creation.
</ResponseField>

<ResponseField name="failure_code" type="string | null">
  A machine-readable code describing why the refund failed. Only present when `status` is `failed`; `null` otherwise. Example values: `expired_or_canceled_card`, `lost_or_stolen_card`.
</ResponseField>

<ResponseField name="metadata" type="object">
  The key-value metadata that was attached to the refund at creation.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the refund was created. Example: `"2024-06-15T10:30:00Z"`.
</ResponseField>

### Example Response

```json
{
  "id": "ref_xyz789abc",
  "object": "refund",
  "payment_id": "pay_abc123xyz",
  "amount": 5000,
  "currency": "usd",
  "status": "succeeded",
  "reason": "requested_by_customer",
  "failure_code": null,
  "metadata": {
    "order_id": "ord_98765"
  },
  "created_at": "2024-06-15T10:30:00Z"
}
```

## Error Responses

| HTTP Status | Error Code | Description |
|---|---|---|
| `404` | `refund_not_found` | No refund with the provided ID was found in your account. Verify that the ID is correct and belongs to your account. |
