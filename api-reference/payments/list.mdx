You can list all payments on your account in reverse chronological order, applying optional filters to narrow results by status or creation date. XPayLabs uses cursor-based pagination — instead of page numbers, each response includes a `next_cursor` value you pass as the `after` parameter to retrieve the following page of results.

## Request

### Query Parameters

<ParamField query="limit" type="integer" optional>
  The number of payment objects to return per page. Accepts a value between `1` and `100`. Defaults to `20`.
</ParamField>

<ParamField query="after" type="string" optional>
  A payment ID cursor. When provided, the response returns payments that come after this ID in the result set (i.e., the next page). Use the `next_cursor` value from a previous response.
</ParamField>

<ParamField query="before" type="string" optional>
  A payment ID cursor. When provided, the response returns payments that come before this ID in the result set (i.e., the previous page). Use the `next_cursor` from earlier responses to navigate backwards.
</ParamField>

<ParamField query="status" type="string" optional>
  Filter results to payments with a specific status. Accepted values: `pending`, `processing`, `succeeded`, `failed`, `canceled`.
</ParamField>

<ParamField query="created[gte]" type="string" optional>
  Return only payments created at or after this [ISO 8601](https://www.iso.org/iso-8601-date-and-time-format.html) timestamp, e.g. `2024-06-01T00:00:00Z`.
</ParamField>

<ParamField query="created[lte]" type="string" optional>
  Return only payments created at or before this ISO 8601 timestamp, e.g. `2024-06-30T23:59:59Z`.
</ParamField>

<Note>
  You can combine `status` and date range filters freely. For example, retrieving all `failed` payments within a specific billing period is a common use case for reconciliation workflows.
</Note>

### cURL

```bash
curl "https://api.xpaylabs.com/v1/payments?limit=10&status=succeeded&created%5Bgte%5D=2024-06-01T00%3A00%3A00Z&created%5Blte%5D=2024-06-30T23%3A59%3A59Z" \
  -H "Authorization: Bearer sk_live_4eC39HqLyjWDarjtT7MDFa"
```

### Node.js

```javascript
const params = new URLSearchParams({
  limit: "10",
  status: "succeeded",
  "created[gte]": "2024-06-01T00:00:00Z",
  "created[lte]": "2024-06-30T23:59:59Z",
});

const response = await fetch(
  `https://api.xpaylabs.com/v1/payments?${params}`,
  {
    headers: {
      Authorization: "Bearer sk_live_4eC39HqLyjWDarjtT7MDFa",
    },
  }
);

const result = await response.json();
console.log(result.data.length);   // up to 10
console.log(result.has_more);      // true if another page exists
```

## Response

A successful request returns HTTP `200 OK` with a paginated list envelope.

### List Envelope

<ResponseField name="data" type="array">
  An array of [Payment objects](/api-reference/payments/retrieve), ordered from newest to oldest. May be empty if no payments match the filters.
</ResponseField>

<ResponseField name="has_more" type="boolean">
  `true` when additional pages of results exist beyond this response. Pass `next_cursor` as the `after` parameter to retrieve the next page. `false` when you have reached the last page.
</ResponseField>

<ResponseField name="next_cursor" type="string">
  The cursor value to use in the `after` query parameter of your next request. Only present when `has_more` is `true`.
</ResponseField>

## Iterating All Pages

To retrieve every payment matching a filter, loop through pages until `has_more` is `false`.

```javascript
async function fetchAllPayments(filters = {}) {
  const allPayments = [];
  let after = null;

  do {
    const params = new URLSearchParams({ limit: "100", ...filters });
    if (after) params.set("after", after);

    const response = await fetch(
      `https://api.xpaylabs.com/v1/payments?${params}`,
      {
        headers: {
          Authorization: "Bearer sk_live_4eC39HqLyjWDarjtT7MDFa",
        },
      }
    );

    if (!response.ok) {
      const error = await response.json();
      throw new Error(error.error.message);
    }

    const page = await response.json();
    allPayments.push(...page.data);
    after = page.has_more ? page.next_cursor : null;
  } while (after !== null);

  return allPayments;
}

// Retrieve all succeeded payments for June 2024
const payments = await fetchAllPayments({
  status: "succeeded",
  "created[gte]": "2024-06-01T00:00:00Z",
  "created[lte]": "2024-06-30T23:59:59Z",
});

console.log(`Total payments: ${payments.length}`);
```

<Warning>
  Fetching large volumes of payments in a tight loop may trigger rate limits. XPayLabs enforces a default limit of 100 requests per second per API key. Consider adding a short delay between pages or processing results incrementally if you are exporting thousands of records.
</Warning>
