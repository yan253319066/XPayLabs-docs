You can retrieve a payment's current status and full details at any time by passing its ID in the URL path. This is useful for polling the outcome of an asynchronous charge, confirming settlement, or surfacing transaction details in your dashboard or support tooling.

## Request

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the payment to retrieve, e.g. `pay_abc123xyz`. Payment IDs are always prefixed with `pay_`.
</ParamField>

### cURL

```bash
curl https://api.xpaylabs.com/v1/payments/pay_abc123xyz \
  -H "Authorization: Bearer sk_test_abc123"
```

### Node.js

```javascript
const paymentId = "pay_abc123xyz";

const response = await fetch(
  `https://api.xpaylabs.com/v1/payments/${paymentId}`,
  {
    headers: {
      Authorization: "Bearer sk_test_abc123",
    },
  }
);

const payment = await response.json();
console.log(payment.status);          // "succeeded"
console.log(payment.settlement_id);   // "stl_3Zp1rQvK"
```

<Tip>
  If you use webhooks, you typically do not need to poll this endpoint — XPayLabs sends a `payment.succeeded` or `payment.failed` event as soon as the status changes. Reserve polling for cases where a webhook delivery may have been missed.
</Tip>

## Response

A successful request returns HTTP `200 OK` and the full [Payment object](#payment-object).

### Payment Object

<ResponseField name="id" type="string">
  Unique identifier for the payment, prefixed with `pay_`. Example: `"pay_abc123xyz"`.
</ResponseField>

<ResponseField name="object" type="string">
  Always `"payment"`.
</ResponseField>

<ResponseField name="amount" type="integer">
  The charged amount in the smallest currency unit, e.g. `4999` for $49.99 USD.
</ResponseField>

<ResponseField name="currency" type="string">
  Lowercase ISO 4217 currency code, e.g. `"usd"`.
</ResponseField>

<ResponseField name="status" type="string">
  Current lifecycle status of the payment. One of:
  - `pending` — received, not yet submitted to the network
  - `processing` — submitted to the card network, awaiting issuer response
  - `succeeded` — funds captured successfully
  - `failed` — declined or errored; see `failure_code` and `failure_message`
  - `canceled` — payment was canceled before capture
</ResponseField>

<ResponseField name="payment_method" type="object">
  Details about the payment method used.

  <Expandable title="payment_method fields">
    <ResponseField name="type" type="string">
      Payment method type. Currently always `"card"`.
    </ResponseField>
    <ResponseField name="card" type="object">
      Card-specific details.

      <Expandable title="card fields">
        <ResponseField name="brand" type="string">
          Card brand, e.g. `"visa"`, `"mastercard"`, `"amex"`.
        </ResponseField>
        <ResponseField name="last4" type="string">
          Last four digits of the card number, e.g. `"4242"`.
        </ResponseField>
        <ResponseField name="exp_month" type="integer">
          Two-digit expiration month, e.g. `8`.
        </ResponseField>
        <ResponseField name="exp_year" type="integer">
          Four-digit expiration year, e.g. `2027`.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="description" type="string | null">
  The description attached to the payment, or `null` if none was provided.
</ResponseField>

<ResponseField name="metadata" type="object">
  Arbitrary key-value pairs attached to the payment at creation time, or an empty object `{}`.
</ResponseField>

<ResponseField name="idempotency_key" type="string | null">
  The idempotency key supplied when the payment was created, or `null`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the payment was created, e.g. `"2024-06-15T10:23:45Z"`.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the most recent update to this payment.
</ResponseField>

<ResponseField name="settlement_id" type="string | null">
  ID of the settlement batch that includes this payment once funds have been captured and grouped for payout. `null` until settlement.
</ResponseField>

<ResponseField name="failure_code" type="string | null">
  Machine-readable failure code when `status` is `"failed"`, e.g. `"card_declined"` or `"expired_card"`. `null` for all other statuses.
</ResponseField>

<ResponseField name="failure_message" type="string | null">
  Human-readable explanation of why the payment failed. `null` when the payment has not failed. Use this for internal debugging, not customer-facing messaging.
</ResponseField>

## Error Responses

### `404 Not Found`

Returned when no payment with the given ID exists on your account.

```json
{
  "error": {
    "type": "invalid_request_error",
    "code": "resource_not_found",
    "message": "No payment found with ID 'pay_abc123xyz'.",
    "param": "id"
  }
}
```

<Warning>
  Payment IDs are scoped to your API key's account. A live-mode key cannot retrieve test-mode payments and vice versa. If you receive a `404` for a known payment, confirm you are using the correct API key mode.
</Warning>
