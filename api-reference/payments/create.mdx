To charge a customer, send a `POST` request to `/v1/payments` with the charge amount, the ISO 4217 currency code, and a payment method token obtained from [XPayLabs.js](https://docs.xpaylabs.com/js) tokenization. XPayLabs processes the charge asynchronously — the returned Payment object will carry an initial status of `pending` or `processing`, which transitions to `succeeded` or `failed` once the issuer responds.

## Request

<Note>
  All amounts must be expressed in the **smallest currency unit**. For USD that means cents: `1000` equals $10.00. For zero-decimal currencies such as JPY, pass the integer value directly (e.g., `1000` = ¥1,000).
</Note>

### Headers

<ParamField header="Idempotency-Key" type="string" optional>
  Pass a unique string in this header to safely retry a payment creation request without risk of double-charging. XPayLabs caches results for 24 hours. If the key matches a prior request, the original response is returned unchanged.
</ParamField>

### Body Parameters

<ParamField body="amount" type="integer" required>
  The charge amount in the smallest currency unit (e.g., `1000` = $10.00 USD). Must be a positive integer greater than zero.
</ParamField>

<ParamField body="currency" type="string" required>
  Three-letter [ISO 4217](https://www.iso.org/iso-4217-currency-codes.html) currency code in lowercase, e.g. `"usd"`, `"eur"`, `"gbp"`.
</ParamField>

<ParamField body="payment_method_token" type="string" required>
  A single-use token representing the customer's payment method, generated by XPayLabs.js on your frontend. Tokens expire after 15 minutes.
</ParamField>

<ParamField body="description" type="string" optional>
  An internal description stored on the payment for your own records. Not shown to customers. Maximum 500 characters.
</ParamField>

<ParamField body="metadata" type="object" optional>
  A set of up to 20 arbitrary key-value pairs you can attach to the payment. Keys and values must be strings. Useful for storing your own order IDs, customer references, or fulfillment state.

  ```json
  {
    "order_id": "ord_9f3k2",
    "customer_tier": "gold"
  }
  ```
</ParamField>

<Tip>
  Always supply an `Idempotency-Key` when creating payments in production. Network timeouts can leave you unsure whether a charge was recorded — a stable key lets you retry safely.
</Tip>

### cURL

```bash
curl -X POST https://api.xpaylabs.com/v1/payments \
  -H "Authorization: Bearer sk_live_4eC39HqLyjWDarjtT7MDFa" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order_8821_attempt_1" \
  -d '{
    "amount": 4999,
    "currency": "usd",
    "payment_method_token": "tok_visa_4242",
    "description": "Subscription — Pro Plan (monthly)",
    "metadata": {
      "order_id": "ord_9f3k2",
      "customer_id": "cus_H7Lmq02xZ"
    }
  }'
```

### Node.js

```javascript
const response = await fetch("https://api.xpaylabs.com/v1/payments", {
  method: "POST",
  headers: {
    Authorization: "Bearer sk_live_4eC39HqLyjWDarjtT7MDFa",
    "Content-Type": "application/json",
    "Idempotency-Key": "order_8821_attempt_1",
  },
  body: JSON.stringify({
    amount: 4999,
    currency: "usd",
    payment_method_token: "tok_visa_4242",
    description: "Subscription — Pro Plan (monthly)",
    metadata: {
      order_id: "ord_9f3k2",
      customer_id: "cus_H7Lmq02xZ",
    },
  }),
});

const payment = await response.json();
console.log(payment.id);      // "pay_7Kx9mNpQ3rLv"
console.log(payment.status);  // "processing"
```

## Response

A successful request returns HTTP `201 Created` and a [Payment object](#payment-object).

### Payment Object

<ResponseField name="id" type="string">
  Unique identifier for the payment, prefixed with `pay_`. Store this to retrieve or reference the payment later. Example: `"pay_7Kx9mNpQ3rLv"`.
</ResponseField>

<ResponseField name="object" type="string">
  Always `"payment"`.
</ResponseField>

<ResponseField name="amount" type="integer">
  The charged amount in the smallest currency unit, exactly as you supplied it.
</ResponseField>

<ResponseField name="currency" type="string">
  Lowercase ISO 4217 currency code, e.g. `"usd"`.
</ResponseField>

<ResponseField name="status" type="string">
  Current lifecycle status of the payment. One of:
  - `pending` — received, not yet submitted to the network
  - `processing` — submitted to the card network, awaiting issuer response
  - `succeeded` — funds captured successfully
  - `failed` — declined or errored; see `failure_code` and `failure_message`
  - `canceled` — payment was canceled before capture
</ResponseField>

<ResponseField name="payment_method" type="object">
  Details about the payment method used.

  <Expandable title="payment_method fields">
    <ResponseField name="type" type="string">
      Payment method type. Currently always `"card"`.
    </ResponseField>
    <ResponseField name="card" type="object">
      Card-specific details.

      <Expandable title="card fields">
        <ResponseField name="brand" type="string">
          Card brand, e.g. `"visa"`, `"mastercard"`, `"amex"`.
        </ResponseField>
        <ResponseField name="last4" type="string">
          Last four digits of the card number, e.g. `"4242"`.
        </ResponseField>
        <ResponseField name="exp_month" type="integer">
          Two-digit expiration month, e.g. `8`.
        </ResponseField>
        <ResponseField name="exp_year" type="integer">
          Four-digit expiration year, e.g. `2027`.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="description" type="string | null">
  The description you provided, or `null` if none was given.
</ResponseField>

<ResponseField name="metadata" type="object">
  The key-value metadata you attached, or an empty object `{}`.
</ResponseField>

<ResponseField name="idempotency_key" type="string | null">
  The idempotency key from the request header, if supplied.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the payment was created, e.g. `"2024-06-15T10:23:45Z"`.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the most recent status change.
</ResponseField>

<ResponseField name="settlement_id" type="string | null">
  ID of the settlement batch this payment belongs to once funds have been captured. `null` until settlement occurs.
</ResponseField>

<ResponseField name="failure_code" type="string | null">
  Machine-readable failure code when `status` is `failed`, e.g. `"card_declined"`, `"insufficient_funds"`. `null` otherwise.
</ResponseField>

<ResponseField name="failure_message" type="string | null">
  Human-readable explanation of the failure. Suitable for your internal logs; do not display this verbatim to customers.
</ResponseField>

## Error Responses

When a request fails, XPayLabs returns a non-2xx HTTP status with a JSON body containing `error.type`, `error.code`, and `error.message`.

### `400 Bad Request` — `invalid_request_error`

Returned when the request body is malformed or a required field is missing or invalid.

```json
{
  "error": {
    "type": "invalid_request_error",
    "code": "missing_required_param",
    "message": "Required parameter 'amount' is missing.",
    "param": "amount"
  }
}
```

Common causes:
- `amount` is missing, zero, or negative
- `currency` is not a recognized ISO 4217 code
- `payment_method_token` is absent or already used

### `402 Payment Required` — `card_error`

Returned when the card issuer declines the charge.

```json
{
  "error": {
    "type": "card_error",
    "code": "card_declined",
    "decline_code": "insufficient_funds",
    "message": "Your card has insufficient funds.",
    "param": "payment_method_token"
  }
}
```

<Warning>
  Do not automatically retry `card_error` responses — the issuer has explicitly declined the card. Ask the customer to use a different payment method instead.
</Warning>

### `422 Unprocessable Entity`

Returned when the request is syntactically valid but cannot be processed — for example, when a duplicate `idempotency_key` is submitted with a different request body.

```json
{
  "error": {
    "type": "idempotency_error",
    "code": "idempotency_key_in_use",
    "message": "An in-flight request with idempotency key 'order_8821_attempt_1' is already being processed. Please retry after it completes."
  }
}
```
