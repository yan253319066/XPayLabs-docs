Test mode is a completely isolated environment within XPayLabs — it runs in parallel with live mode but shares no data with it. When you use a `sk_test_...` API key, every API call, payment object, refund, and payout you create exists only in the test environment. No real money moves, no real bank accounts are charged, and test data never appears in your live Dashboard. This lets you build and verify your entire integration safely before going live.

<Note>
  Test mode and live mode are completely separate environments. A payment created with `sk_test_abc123` will never appear under your live Dashboard, and live payments are never visible in test mode. Always confirm which key your server is using before deploying to production.
</Note>

## Test API Keys

Use your `sk_test_...` secret key on your server and your `pk_test_...` publishable key in the browser. You can find both in the **Developers → API Keys** section of your XPayLabs Dashboard.

```bash
# Test environment
Authorization: Bearer sk_test_abc123

# Live environment (use only in production)
Authorization: Bearer sk_live_...
```

## Test Card Numbers

Use the following card numbers to simulate specific payment outcomes in test mode. Pair any of them with a future expiry date (e.g., `12/34`) and any 3-digit CVC (e.g., `123`).

| Card Number | Outcome |
|---|---|
| `4242 4242 4242 4242` | Payment succeeds |
| `4000 0000 0000 0002` | Card declined (generic) |
| `4000 0000 0000 9995` | Insufficient funds |
| `4000 0000 0000 0069` | Expired card |
| `4000 0000 0000 0127` | Incorrect CVC |
| `4000 0027 6000 3184` | Requires 3D Secure authentication |

For cards that require 3D Secure (`4000 0027 6000 3184`), your integration must handle the `requires_action` status and call `xpay.handleNextAction()` (or redirect to `next_action.redirect_to_url.url`). In test mode, the 3DS challenge page has **Authenticate** and **Fail Authentication** buttons so you can test both outcomes.

<Info>
  Use any future expiry date and any 3-digit CVC with the test cards above. For American Express test cards, use a 4-digit CVC. The billing postal code field, if shown, accepts any 5-digit value (e.g., `10001`).
</Info>

## Test Card Example

```bash
curl -X POST https://api.xpaylabs.com/v1/payments \
  -H "Authorization: Bearer sk_test_abc123" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 4999,
    "currency": "usd",
    "payment_method_token": "tok_visa_4242",
    "description": "Test order"
  }'
```

When you tokenize the test card `4242 4242 4242 4242` using XPayLabs.js in test mode, it returns a token like `tok_visa_4242`. You can also use pre-built test tokens listed in the Dashboard under **Developers → Test Data**.

## Testing Webhooks

You don't need a public HTTPS endpoint to test webhooks during development. Use the **Dashboard webhook tester** to send sample events directly to any URL — including `localhost` via a tunneling tool like ngrok.

**To test webhooks using the Dashboard:**

1. Go to **Developers → Webhooks** in your Dashboard.
2. Select your webhook endpoint (or create a new one).
3. Click **Send test event** and choose an event type (e.g., `payment.succeeded`).
4. XPayLabs sends a signed POST request to your endpoint with a realistic sample payload.

**To test webhooks locally with ngrok:**

```bash
# Start your local server on port 3000
node server.js

# In a second terminal, expose it via ngrok
ngrok http 3000
```

Register the ngrok HTTPS URL (e.g., `https://a1b2c3d4.ngrok.io/webhooks/xpaylabs`) as a webhook endpoint in the Dashboard. All test events will be forwarded to your local server in real time.

## Test Payouts

To test payouts in test mode, add a test recipient in your Dashboard under **Recipients** using the bank account details below. XPayLabs recognises these values and keeps the funds within the test environment — no real bank account is touched.

| Field | Test Value |
|---|---|
| Routing number | `110000000` |
| Account number | `000123456789` |
| Account type | `checking` |
| Country | `US` |
| Currency | `usd` |

Once the test recipient is verified, call `POST /v1/payouts` with its ID to create a test payout:

```bash
curl -X POST https://api.xpaylabs.com/v1/payouts \
  -H "Authorization: Bearer sk_test_abc123" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: test-payout-001" \
  -d '{
    "recipient_id": "rec_xyz789",
    "amount": 25000,
    "currency": "usd",
    "description": "Test payout"
  }'
```

Test payouts transition through `pending` → `in_transit` → `paid` automatically within a few seconds in test mode, so you can verify your status-handling logic without waiting for real banking timelines.

## Simulating Specific Payout Failures

Append a special suffix to the test account number to force a specific failure code:

| Account Number | Simulated Failure |
|---|---|
| `000111111113` | `insufficient_funds` |
| `000111111116` | `invalid_account` |
| `000111111119` | `account_closed` |

## Switching to Live Mode

When your integration is working correctly in test mode, follow these steps to go live:

<Steps>
  <Step title="Complete identity and business verification">
    Go to **Settings → Account** in your Dashboard and complete the KYB (Know Your Business) verification form. XPayLabs requires legal business information and identity verification before live payments can be processed.
  </Step>

  <Step title="Connect your bank account">
    Navigate to **Settings → Bank Account** and add the bank account where XPayLabs will settle your funds. You'll need to verify ownership via micro-deposits or instant verification.
  </Step>

  <Step title="Replace your API keys">
    Swap every instance of `sk_test_...` with your `sk_live_...` secret key and `pk_test_...` with your `pk_live_...` publishable key. Store live keys exclusively in environment variables — never hard-code them or commit them to source control.

    ```bash
    # .env (production)
    XPAYLABS_SECRET_KEY=sk_live_...
    XPAYLABS_PUBLISHABLE_KEY=pk_live_...
    XPAYLABS_WEBHOOK_SECRET=whsec_live_...
    ```
  </Step>

  <Step title="Enable webhook signature verification">
    In **Developers → Webhooks**, copy the live webhook signing secret (`whsec_live_...`) and update your `XPAYLABS_WEBHOOK_SECRET` environment variable. Verify that your endpoint correctly validates the `x-xpaylabs-signature` header on every incoming event.
  </Step>
</Steps>
