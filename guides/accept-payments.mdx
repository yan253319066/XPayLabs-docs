Building a payment acceptance flow with XPayLabs lets you securely collect and process payments from customers around the world. The integration combines a lightweight client-side library — XPayLabs.js — with a server-side API call to create a PaymentIntent. This separation ensures that raw card data never touches your servers, keeping you out of PCI scope while giving you full control over the checkout experience.

## Supported Payment Methods

| Method | Type | Regions |
|---|---|---|
| Visa / Mastercard | Card | Global |
| American Express | Card | Global |
| Apple Pay | Digital Wallet | iOS / macOS Safari |
| Google Pay | Digital Wallet | Android / Chrome |
| Local methods (iDEAL, SEPA, Boleto, etc.) | Local | Region-specific |

## Integration Steps

<Steps>
  <Step title="Collect payment details (client-side)">
    Use **XPayLabs.js** or the hosted fields embed to tokenize card data directly in the browser. The library communicates with XPayLabs servers and returns a short-lived `payment_method_token` — your server never sees the raw card number.

    Add the script to your checkout page:

    ```html
    <script src="https://js.xpaylabs.com/v1/xpaylabs.js"></script>
    ```

    Initialize the hosted card field and mount it to a container element:

    ```javascript
    const xpay = XPayLabs("sk_test_abc123");
    const cardField = xpay.elements().create("card");
    cardField.mount("#card-element");

    // When the customer submits the form, tokenize the card
    const form = document.getElementById("payment-form");
    form.addEventListener("submit", async (e) => {
      e.preventDefault();
      const { token, error } = await xpay.createToken(cardField);
      if (error) {
        // Display error.message to the customer
        document.getElementById("error-message").textContent = error.message;
      } else {
        // Send token.id to your server as payment_method_token
        await submitPayment(token.id);
      }
    });
    ```

    <Note>
      XPayLabs's hosted fields are rendered in an XPayLabs-owned iframe. Because raw card data is tokenized entirely within that iframe, your integration qualifies for the simplest PCI DSS compliance tier (SAQ A) — you never handle, store, or transmit cardholder data.
    </Note>
  </Step>

  <Step title="Create a PaymentIntent (server-side)">
    Once you have a `payment_method_token` from the client, send it to your server and create a PaymentIntent by calling `POST /v1/payments`. Always specify `amount` in the smallest currency unit (e.g., cents for USD).

    ```javascript
    // Node.js / Express example
    const express = require("express");
    const axios = require("axios");
    const app = express();

    app.use(express.json());

    app.post("/api/create-payment", async (req, res) => {
      const { paymentMethodToken, amount, currency } = req.body;

      try {
        const response = await axios.post(
          "https://api.xpaylabs.com/v1/payments",
          {
            amount,                          // e.g. 4999 for $49.99
            currency,                        // e.g. "usd"
            payment_method_token: paymentMethodToken,
            description: "Order #1042",
            metadata: { order_id: "1042" },
          },
          {
            headers: {
              Authorization: `Bearer ${process.env.XPAYLABS_SECRET_KEY}`,
              "Content-Type": "application/json",
              "Idempotency-Key": `order-1042-${Date.now()}`,
            },
          }
        );

        res.json({ payment: response.data });
      } catch (err) {
        res.status(400).json({ error: err.response?.data ?? err.message });
      }
    });

    app.listen(3000);
    ```

    **Required fields for `POST /v1/payments`:**

    | Field | Type | Description |
    |---|---|---|
    | `amount` | integer | Amount in smallest currency unit (e.g., cents) |
    | `currency` | string | ISO 4217 currency code (e.g., `usd`, `eur`) |
    | `payment_method_token` | string | Token returned by XPayLabs.js |
    | `description` | string | Optional human-readable label for the payment |
    | `metadata` | object | Optional key-value pairs for your internal records |
    | `idempotency_key` | string | Optional unique key to prevent duplicate charges |
  </Step>

  <Step title="Handle the response">
    The API returns a payment object. Inspect the `status` field to determine next steps:

    ```json
    {
      "id": "pay_abc123xyz",
      "object": "payment",
      "amount": 4999,
      "currency": "usd",
      "status": "succeeded",
      "payment_method_token": "tok_visa_4242",
      "description": "Order #1042",
      "created_at": "2024-06-01T12:34:56Z"
    }
    ```

    | Status | Meaning | Action |
    |---|---|---|
    | `succeeded` | Payment captured successfully | Fulfill the order |
    | `requires_action` | Strong customer authentication needed | Follow Step 4 |
    | `failed` | Payment declined or errored | Show failure message; prompt retry |

    For `failed` payments, the response also includes a `failure_code` and `failure_message` field you can display to the customer (e.g., `"card_declined"`, `"insufficient_funds"`).
  </Step>

  <Step title="Handle 3DS / requires_action">
    When `status` is `requires_action`, the response includes a `next_action` object describing what your client must do. The most common type is `redirect_to_url` for 3D Secure authentication.

    ```json
    {
      "id": "pay_abc123xyz",
      "status": "requires_action",
      "next_action": {
        "type": "redirect_to_url",
        "redirect_to_url": {
          "url": "https://hooks.xpaylabs.com/3ds/auth?session=sess_xyz",
          "return_url": "https://yoursite.com/checkout/complete"
        }
      }
    }
    ```

    Use XPayLabs.js to handle this automatically — it manages the redirect or modal display transparently:

    ```javascript
    const { payment, error } = await xpay.handleNextAction(paymentId);
    if (error) {
      // Authentication failed — show error to customer
    } else if (payment.status === "succeeded") {
      // Authentication succeeded — fulfill order
    }
    ```

    If you prefer to redirect manually, send the customer to `next_action.redirect_to_url.url`. After authentication, XPayLabs redirects back to your `return_url` with a `payment_id` query parameter.
  </Step>

  <Step title="Confirm payment success">
    After handling any required actions, confirm the final payment state through either of these approaches:

    **Option A — Webhooks (recommended):** Register a `payment.succeeded` webhook in your Dashboard. XPayLabs sends a signed POST request to your endpoint when the payment is captured. This is the most reliable method because it works even if the customer closes their browser.

    ```javascript
    app.post("/webhooks/xpaylabs", express.raw({ type: "application/json" }), (req, res) => {
      const signature = req.headers["x-xpaylabs-signature"];
      let event;

      try {
        event = xpay.webhooks.constructEvent(
          req.body,
          signature,
          process.env.XPAYLABS_WEBHOOK_SECRET
        );
      } catch (err) {
        return res.status(400).send(`Webhook signature verification failed: ${err.message}`);
      }

      if (event.type === "payment.succeeded") {
        const payment = event.data.object; // pay_abc123xyz
        // Fulfill the order for payment.metadata.order_id
      }

      res.json({ received: true });
    });
    ```

    **Option B — Poll the API:** Retrieve the payment by ID until its status is terminal:

    ```bash
    curl https://api.xpaylabs.com/v1/payments/pay_abc123xyz \
      -H "Authorization: Bearer sk_test_abc123"
    ```
  </Step>
</Steps>

## Complete Server-Side Example

The following Express endpoint combines all server-side steps into a single, production-ready handler:

```javascript
const express = require("express");
const axios = require("axios");
const { v4: uuidv4 } = require("uuid");

const router = express.Router();

router.post("/checkout", async (req, res) => {
  const { paymentMethodToken, amount, currency, orderId } = req.body;

  if (!paymentMethodToken || !amount || !currency || !orderId) {
    return res.status(422).json({ error: "Missing required fields." });
  }

  try {
    const { data: payment } = await axios.post(
      "https://api.xpaylabs.com/v1/payments",
      {
        amount,
        currency,
        payment_method_token: paymentMethodToken,
        description: `Order #${orderId}`,
        metadata: { order_id: orderId },
      },
      {
        headers: {
          Authorization: `Bearer ${process.env.XPAYLABS_SECRET_KEY}`,
          "Content-Type": "application/json",
          "Idempotency-Key": `checkout-${orderId}-${uuidv4()}`,
        },
      }
    );

    switch (payment.status) {
      case "succeeded":
        // Mark order as paid in your database
        return res.json({ status: "succeeded", paymentId: payment.id });

      case "requires_action":
        // Return next_action details to the client
        return res.json({
          status: "requires_action",
          paymentId: payment.id,
          nextAction: payment.next_action,
        });

      case "failed":
        return res.status(402).json({
          status: "failed",
          failureCode: payment.failure_code,
          message: payment.failure_message,
        });

      default:
        return res.status(500).json({ error: "Unexpected payment status." });
    }
  } catch (err) {
    console.error("Payment creation error:", err.response?.data ?? err.message);
    return res.status(500).json({ error: "Payment processing failed. Please try again." });
  }
});

module.exports = router;
```
